# AERIS 介面、操作透明度與技能範例規格

版本：1.0；Blueprint revision：0.7.0-governance.3；日期：2026-09-08。
範圍：100 席聲學工程 AI 公司的設計與驗收要求。本文發布不代表介面、技能範例或真實工程能力已實作；實作狀態 NOT VERIFIED，E 全面本機驗收 NOT_STARTED。

## 三個參考各自負責什麼

| 參考 | AERIS 採納的設計方向 | 不據此推定的事情 |

| [雷小蒙／Kairos](https://os.lifehacker.tw/) | 整體 UX/UI、導覽、卡片、分類、工作紀錄與能力圖譜 | 不推定密碼保護內頁或後端架構；不複製品牌、文案與成果數字 |
| [Agent Zero](https://www.agent-zero.ai/) | 本機代理、工具、記憶、工作流程的呈現與操作透明度 | 不代表已採用其程式碼、執行框架或安全模型 |
| [氛圍學院](https://academy.vibetech.tw/home)／哈利說的「AI 時代軟體必修課」 | 技能範例、互動練習、白話解說，讓使用者邊看邊操作 | 只採納使用者指定的教學方向；未驗證課程內頁、套件、價格、卡片數或服務規格 |

三者是分工參考，AERIS Blueprint 仍是唯一設計真相。所有功能須符合聲學需求、權限與 Evidence Hard Gates。任何第三方程式碼或執行框架的採用，另做授權、安全性、相容性及維護成本評估；本規格不新增外部服務、付費 API 或安裝依賴。

## UX-01 — Kairos 視覺與導覽

- 採用窄側邊導覽、適當留白與青綠色重點，保留卡片與資訊層級。延續 [UI v0.5 研究](../research/2026-09-01_Kairos_User_Screenshot_UI_Calibration_v0.5.md)，不把估計尺寸當成來源網站的原始 CSS。
- 卡片分類回答「能做什麼、正在做什麼、還缺什麼」。工作紀錄連到真實任務及產物；能力圖譜區分 100 個專業席位、可用技能和各自驗證狀態。
- 主要導覽、表單、空白狀態、錯誤和說明使用繁體中文；專有名詞首次附白話解釋。圖示提供繁中名稱、鍵盤 focus 與可存取名稱；手機點按也能取得導覽名稱，不依賴 hover。
- 首頁優先呈現「我要解決什麼聲學問題、目前進度、需要我決定什麼」，不以長篇角色自述取代工作入口。
- 色彩不是唯一狀態提示。提供文字標籤與明確錯誤原因；亮暗主題、窄螢幕與放大文字均不得遮住主要操作。

驗收：在桌面與手機寬度、亮暗主題及鍵盤操作下檢查主要任務路徑；圖示能辨識、文字可讀、無主要操作截斷。保存畫面、測試尺寸及結果。角色／技能／任務數不得顯示為工程驗證完成率。

## UX-02 — Agent Zero 操作透明度

Agent Zero 為 AERIS 的互動方式與操作透明度參考。AERIS 參考其本機代理、工具、記憶與工作流程的呈現方向，設計繁體中文操作介面。

任務顯示五步：「說明問題 → 挑選專家 → 執行分析 → 檢查證據 → 由你核准」。可展開查看角色責任、工具名稱／版本、輸入與輸出參照、開始／結束時間、失敗原因、下一步及所需人類核准。呈現可稽核的動作紀錄與簡要理由，不要求暴露模型內部推理。

對話記憶、專業知識、工程證據分開標示來源和用途；記憶與 RAG 檢索結果不是量測事實。UI 不顯示秘密值或未授權私人資料。模型離線、缺工具或證據時須如實顯示阻擋，不能展示虛構執行紀錄。

驗收：使用成功、工具失敗、模型未連線、缺 Evidence 及需人核准案例，對照畫面與實際事件／產物；所有紀錄都能追溯，未知不得顯示 PASS。

## EX-01 — 每個技能都有繁中範例

適用所有登錄 Skill，包含既有、新增、分析、治理、報告及外部工具技能；不是只有 100 個 Role。可共用素材，但每個技能必須有自己的 skill ID、適用情境、預期輸出與驗收對應。

| 必填內容 | 使用者看得懂的呈現 |
|---|---|
| 用途與情境 | 一句話說明能解決什麼聲學或工程問題 |
| 輸入與條件 | 範例資料、來源／授權、單位、必要工具、版本與限制 |
| 操作步驟 | 載入範例 → 操作 → 看結果 → 在安全範圍改參數再試 |
| 預期結果 | 執行前固定 Expected Result，數值附單位及適用 tolerance |
| 結果圖解 | 圖表／報告／輸出預覽與繁中解說，不只貼原始 JSON |
| 可重現紀錄 | 執行方式、版本／資料 digest、Actual Result、PASS／FAIL、產物 hash、Requirement ID |
| 失敗與限制 | 至少一個錯誤輸入、邊界或不適用案例，解釋為什麼拒絕或需補資料 |

資料與範例自行製作或採合法授權來源；不複製付費課程內容。介面可預覽範例，但執行前需說明會產生的變更與必要權限；不因「載入範例」自動安裝、花費或發布。

## EX-02 — 教學展示不等於專業驗收

每個範例明示 `展示預覽`、`合成資料練習` 或 `真實量測案例`。再分別顯示 `範例執行結果` 與 `技能專業驗證狀態`，不可由前者自動升級後者。

外部設備／授權尚未具備的技能仍須提供教學情境、預期輸出預覽和前置需求，但標示 BLOCKED_EXTERNAL／NOT VERIFIED；預覽不是已執行證據。缺少範例或必要 Evidence 的技能不得標示為已驗證。

既有驗證紀錄保留，不回寫或偽造舊證據；新增範例要求未滿足時，現行綜合狀態須呈現待補與 NOT VERIFIED。範例、方法或版本改變會使受影響的舊範例驗證失效。

驗收：逐技能核對範例覆蓋表；測試缺範例、缺證據、舊版本證據、合成資料冒充量測、硬體缺席五種負例，均不得顯示已驗證。報告顯示分母、待補技能及外部阻擋，不以教材數量推算專業成熟度。

## EX-03 — 頻譜分析示例的設計

情境：「風扇有尖銳聲，先學會看聲音集中在哪個頻率」。入門練習先用自製、已知頻率的 1 kHz 合成訊號，不把它描述成風扇量測。

範例應固定 sample rate、時長、振幅、窗函數及 FFT 設定，事先定義峰值位置容許差，再執行分析、顯示頻譜與 Actual Result。讓使用者改頻率觀察峰值移動；另示範無效 sample rate 或不支援格式如何被拒絕。

白話說明：「找到頻率峰值，只表示這個頻率成分突出，還不能證明實際風扇的噪音原因。」真實診斷另需 RPM、麥克風位置、校正、環境及量測證據。本段僅設計範例，未生成音檔、未執行 FFT、未宣稱測試通過。
